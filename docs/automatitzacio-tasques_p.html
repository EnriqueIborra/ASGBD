Automatització de tasques

Automatització

L'automatització consisteix en fer tasques de manera sistemàtica i repetitiva sense que estiga involucrat un usuari en la seua execució

Quan parlem d’automatització en postgresql, generalment ens referim a processos que es programen per executar-se automàticament, sense necessitat d’intervenció manual. postgresql ofereix diverses eines i mètodes per fer això

Avantatges Automatització

  • Estalvi de temps
  • Reducció costos administració
  • Reducció errors ( humà)

Tipus

  • Programa extern (al SGBD)
    • Programador de Tasques de Windows, Crontab en Linux, etc..
    • pgAgent
  • Programa intern : jobs = pg_cron + cron.schedule()

Rutina

  • Script, guió, programa o seqüència de comandos que permeten dur a terme el processament d'unes certes accions
  • Quan és creada rep un nom que permet que siga invocada tantes vegades com siga necessari

SQL (Structured Query Language) és un llenguatge declaratiu. S’utilitza per gestionar i consultar bases de dades. No té estructures de control com bucles o condicions complexes. SELECT (consultar dades), INSERT (inserir dades), UPDATE (actualitzar dades), DELETE (esborrar dades), i altres com DDL, DCL, TCL

PL/pgSQL (Procedural Language /PostgreSQL Structured Query Language). És una adaptacio de PL/SQL creada per Oracle, a Postgres. És un llenguatge procedimental. Permet utilitzar: Variables, Condicions (IF), Bucles (LOOP, WHILE, FOR), Procediments i funcions. S’utilitza per crear programs dins de la base de dades.

El SGBD deu proporcionar:

  • Eines necessàries per a crear rutines
  • Eines per a executar les rutines automàticament

Avantatges rutina interna

  • Rendiment
  • Reutilització de codi
  • Encapsula regles de negoci
  • Major seguretat

🧾 Bloc DO en PL/pgSQL

Què és un bloc DO ?

Un bloc DO és una unitat de codi en PL/pgSQL que:

  • No té nom ni es guarda a la base de dades.
  • S’executa directament des de la pestanya. Es pot guardar en un fitxer extern i després recuperar.
  • És ideal per a proves o per a executar operacions puntuals.
  • Pot incloure sentències SQL, declaracions de variables, control de flux, i gestió d’excepcions.

En psql es pot:

\p           Vore el contingut del buffer 
\e           Editar el contingut del buffer
\r           Neteja el buffer 
\g           Executa la consulta del buffer
\w nom.sql   Guardar el contingut del buffer en un arxiu
\w nom.sql   Carrega el contingut d'un fitxer en el buffer (però NO  l'executa)      
\i nom.sql   Carrega i executa el contingunt d'un fitxer
\ir nom.sql  Executa un fitxer SQL amb ruta relativa al directori del fitxer actual
\s           Mostra l'historial d'ordres.
\!           Ix a una shell d'on es pot tornar amb "exit"
\!             Executa una ordre del sistema operatiu.
\cd directori  Canvia el directori de treball.
\o fitxer.txt  Redirigeix l'eixida de les consultes a un fitxer.
\o             Torna a mostrar l'eixida per pantalla.
\?           Mostra l'ajuda de les metacomandes.
\h           Mostra l'ajuda de les instruccions SQL.

\p, \i, \g, etc. són metacomandes pròpies de psql, no instruccions SQL del servidor PostgreSQL.

Estructura bàsica d’un bloc DO 

DO $$
BEGIN
    RAISE NOTICE 'Hola món';
END;
$$ LANGUAGE plpgsql;

Per executar este bloc DO, s'ha de fer amb F5 (script), en l'altre cas, en executar sentència, donarà un error: 'ERROR: unterminated dollar-quoted string at or near "$$' perquè sols arriba fins al primer ";"

Exemple

DO $$
declare
 i int;
BEGIN
    i := 445;
    RAISE NOTICE 'Hola món';
	RAISE NOTICE 'valor de i %', i;
	RAISE NOTICE 'valor de i*i %', i*i ;
	RAISE NOTICE 'hui es   %', current_date;
END;
$$ LANGUAGE plpgsql;

PL/pgSQL és case-sensitive respecte als noms de variables, funcions i identificadors.

DO $$
DECLARE
    x_valor int := 10;
    X_VALOR int := 20;
BEGIN
    RAISE NOTICE 'x_valor = %, X_VALOR = %', x_valor, X_VALOR;
END;
$$ LANGUAGE plpgsql;

Variables

Una variable en PL/pgSQL és un espai de memòria per emmagatzemar dades temporals durant l'execució d’un bloc de codi. Pot contindre textos, números, dates, etc.

En PL/pgSQL, les variables s’han de declarar sempre abans d’utilitzar-les. Les variables es declaren a la secció DECLARE (o a la part de declaració d’un procediment, funció o paquet).

Per "crear" una variable és necessari:
Un nom
Un tipus
Un valor (opcional)

Per "usar" una variable, sols és necessari saber el nom

Estructura bàsica

DO $$
DECLARE
    nom_variable tipus ;        -- Es declara però no s'inicialitza. Pren el valor NULL   
    nom_variable tipus := valor_inicial;  -- Es declara i s'inicialitza amb un valor  
BEGIN
    -- ús de la variable
END; 
$$ LANGUAGE plpgsql; 
-- Tipus de dades en PL/pgSQL

numeric(p,s)  (decimals amb límit)

DATE         (any,mes,dia)
TIMESTAMP    (any,mes,dia, hora, min, seg, part de segon)
RECORD

int[]         (ARRAY de ints)

DO $$
DECLARE
    v_nom       text := 'Anna';
    v_edat      int DEFAULT 30;   -- tots dos són vàlids
    v_sou       numeric := 8.27;

END;
$$ LANGUAGE plpgsql;

🛠️ Com assignar valors

-- En el bloc DECLARE

 v_nom       text := 'Anna';

-- En el bloc principal BEGIN

  • Assignació directa: v_edat := 25;
  • Amb SELECT INTO: 
    SELECT sou INTO v_sou FROM empleats WHERE id = 5;
            o

❗ Detalls importants

  • Les variables només existeixen dins del bloc on es declaren.
  • No pots fer SELECT ... sense INTO dins de PL/pgSQL.
  • BOOLEAN només es pot usar dins de PL/pgSQL, no en SQL estàndard.

Operacions

Operacions amb Variables en PL/pgSQL

Una vegada declarades, les variables en PL/pgSQL poden utilitzar-se per fer càlculs, tractament de text, dates i lògica condicional. Ací tens exemples clars i útils:

📐 1. Operacions aritmètiques

Per fer sumes, restes, multiplicacions, divisions i potències amb variables de tipus NUMBER:

DO $$
DECLARE
    a int := 10;
    b int := 3;
    resultat1 int;
BEGIN
    resultat1 := a + b;
    raise notice ' %' ,resultat1 ;	
    resultat1 := a - b;
    raise notice ' %' ,resultat1 ;	
    resultat1 := a * b;
    raise notice ' %' ,resultat1 ;	
    resultat1 := a / b;
    raise notice ' %' ,resultat1 ;	
    resultat1 := a % b;
    raise notice ' %' ,resultat1 ;
END;
$$ LANGUAGE plpgsql;

Precedència: No s'ha d'oblidar que no és el mateix 2 + 5 * 3 que (2 + 5) * 3. La precedència o ordre de les operacions és crucial en el resultat

En PL/pgSQL este ordre de precedència és el següent:

( ) unaris ** potència * , /, mod + i - comparació lògics (NOT AND OR)
I els operadors lògics tenen precedència entre ells. NOT té més precedència que AND i AND més que OR,

Encara que conegues la precedència, usa parèntesis per fer el codi: *més clar, *menys propens a errors, *més llegible per altres desenvolupadors

Altres operacions aritmètiques amb funcions: ABS, ROUND, MOD, CEIL, CEILING FLOOR, POWER, SQRT, TO_CHAR

🔤 2. Operacions amb cadenes de text (strings)

Les cadenes (VARCHAR) es concatenen amb || 

DO $$
DECLARE
    nom VARCHAR(20) := 'Joan';
    cognom VARCHAR(20) := 'Garcia';
    nom_complet VARCHAR(50);
BEGIN
    nom_complet := nom || ' ' || cognom;
    RAISE NOTICE 'Nom complet: %', nom_complet;
END;
$$ LANGUAGE plpgsql;

Altres operacions sobre cadenes (strings) amb funcions: LENGTH, UPPER, LOWER, INITCAP, SUBSTRING, POSITION, REPLACE, TRIM, LTRIM, RTRIM, TO_NUMBER

📅 3. Operacions amb dates

Les dates son un tipus de dada diferent als nombres i als strings. Serveixen per "marcar" un moment concret del temps. Les dates es poden comparar, per saber quina data es anterior o posterior.
Les dates es poden restar per obtenir la diferència (resultat en dies, i hores/min). Este resultat és un interval de temps
A les dates també se li pot sumar un interval.

Depenent de la precisió requerida, hi ha dos subtipus de dates: DATE i TIMESTAMP

✔️ El tipus "DATE" pot emmagatzemar fins al dia. (Any, mes, dia)
Si es necessita més precisió, es pot utilitzar el tipus "TIMESTAMP", el qual pot emmagatzemar fins a milionèsima de segon (Exemple d'un valor de tipus TIMESTAMP: 2026-03-22 15:57:59.811083)

Hi ha dos funcions que ens diuen la data actual

CURRENT_DATE  -- retorna la data actual.  
now()         -- retorna la data i l'hora actuals   
DO $$
DECLARE
  d1 date ;
  d2 date;
  resultat1 int;
BEGIN
  d1 := CURRENT_DATE;
  d2 := date '2026-01-01';
  resultat1 := d1 - d2 + 8;
  raise notice ' %' ,resultat1 ;	
END;
$$ LANGUAGE plpgsql;    
-- Exemples d'operacions amb dates
SELECT CURRENT_DATE + 7 AS setmana_propera;
SELECT date '2026-03-22' - date '2026-03-20' AS dies_diff;
SELECT CURRENT_DATE + interval '1 month' AS mes_proper;
SELECT CURRENT_DATE - interval '2 weeks' AS fa_dos_setmanes;  
--Comparacions
SELECT '2026-03-22'::date > '2026-03-20'::date;  -- true
SELECT NOW() BETWEEN '2026-09-22 00:00' AND '2026-12-22 23:59';

TO_DATE() i TO_CHAR()

les funcions TO_DATE() i TO_CHAR() serveixen per convertir dates i hores entre formats.

  • TO_DATE(): converteix un text (text) en una data (date).
  • TO_CHAR(): converteix una data o un valor numèric en text (text) amb un format determinat.
--  sintaxi 
TO_DATE(text, format)   
-- El segon paràmetre indica com està escrit el text original per saber interpretar-lo.
-- Exemple
SELECT TO_DATE('30/10/2026', 'DD/MM/YYYY');  
-- sintaxi
TO_CHAR(valor, format) 
-- Exemple:
SELECT TO_CHAR(CURRENT_DATE, 'DD/MM/YYYY');

Possibles valors en la màscara:
DD Dia del mes -- MM Mes numèric -- YYYY Any amb quatre xifres -- YY Any amb dos xifres
HH Hora -- HH24 Hora (format 24 h) -- MI Minuts -- SS Segons
Els altres caràcters s'interpretarans tal qual estan. 

DO $$
DECLARE
    v_data TIMESTAMP := NOW();
    v_data_text TEXT;
BEGIN
    -- Convertir timestamp en text
    v_data_text := TO_CHAR(v_data, 'DD/MM/YYYY HH24:MI:SS');

    RAISE NOTICE 'Data i hora actual: %', v_data_text;
END;
$$ LANGUAGE plpgsql;

S'ha d'anar amb cura en les operacions amb dates, perquè tots els mesos no tenen el mateix nombre de dies, ni tots els anys tampoc tenen el mateix nombre de dies !!

Les dates s'han de guardar i tractar com a dates (DATE o TIMESTAMP), no com a cadenes de text. !!

4. Operacions lògiques

Amb variables BOOLEAN, pots fer condicions:

AND OR NOT

Es pot utilitzar variables o expresions BOOLEAN, o fer comparacions entre nombres, textos o dates amb els operadors següents:

  • = igualtat
  • <> diferent
  • >, <, >=, <=
  • AND, OR, NOT

✨ Totes les expresions condicionals tornen un valor BOOLEAN (true / false).

CASE Sensitive

En PL/pgSQL: 'admin' no és igual que 'ADMIN'
Es poden comparar amb < o > també de manera que les cadenes es comparen caràcter per caràcter, segons l’ordre lexicogràfic (semblant a l’ordre del diccionari).

'Ana' < 'Berta'     -- TRUE
'abc' < 'abd'       -- TRUE
'Z' < 'a'           -- TRUE (perquè el codi ASCII de Z és menor)

Buscar patrons dins d'un text.

Les cadenes de text també es poden comparar amb LIKE, usant '%'=>(qualsevol quantitat de caracters) o '_'=>(un sol caracter)

nom LIKE 'Mar%' 
v_nom LIKE 'M_ria'    
DO $$
DECLARE
    v_nom TEXT := 'Maria';
    vb boolean ;
BEGIN
    vb := v_nom LIKE 'Mar%';
    RAISE NOTICE 'Copmença per Mar? : %',vb  ;
 END;
$$ LANGUAGE plpgsql;

🔁 Estructures de control en PL/pgSQL

Les estructures de control són fonamentals per controlar el flux d'execució d’un bloc de codi PL/pgSQL. Les principals són: Condicionals i Bucles

Condicionals

Estructura IF simple

L'estructura IF permet executar diferents instruccions en funció de si es compleix una condició.

IF condicio THEN
    instruccions;
END IF;

Estructura IF amb ELSE

L'estructura IF permet executar diferents instruccions SI es compleix la condició i altres SINO es compleix la condició.

IF condicio THEN
    instruccions;
ELSE
    instruccions;
END IF;

Estructura IF ampliada amb ELSIF

ELSIF permet comprovar una nova condició quan la condició anterior no s'ha complit. D'aquesta manera, podem encadenar diverses condicions dins d'una mateixa estructura IF. Les condicions s'avaluen en ordre, de dalt cap avall. S'executen les instruccions del primer bloc que tinga una condició certa. La resta s'ignoren.

Els ELSIF van tots entre el IF i el ELSE 

IF condicio THEN
    instruccions;
ELSIF altra_condicio THEN
    instruccions;
ELSE
    instruccions;
END IF;

El ELSE i ELSEIF són opcionals

Exemple IF (🧪 Prova-ho!)

DO $$
DECLARE
    x int := 3;
BEGIN
    IF x > 5 THEN
        RAISE NOTICE 'x és major que 5';
    ELSE
        RAISE NOTICE 'x és menor o igual a 5';
    END IF;
END;
$$ LANGUAGE plpgsql;        
-- Exemple amb ELSEIF
DO $$
DECLARE
    x int := 5;
BEGIN
    IF x > 5 THEN
        RAISE NOTICE 'Major que 5';
    ELSIF x = 5 THEN
        RAISE NOTICE 'Igual a 5';
    ELSE
        RAISE NOTICE 'Menor que 5';
    END IF;
END;
$$ LANGUAGE plpgsql;

Estructura CASE

L'estructura CASE permet executar diferents instruccions en funció del valor d'una expressió o del compliment de diverses condicions.

És una alternativa a l'estructura IF ... ELSIF ... ELSE quan necessitem avaluar diferents possibilitats.

CASE expressio
    WHEN valor1 THEN instruccions;
    WHEN valor2 THEN instruccions;
    ELSE instruccions;
END CASE;  
o 
CASE 
    WHEN expressio1 THEN instruccions;
    WHEN expressio2 THEN instruccions;
    ELSE instruccions;
END CASE;

Exemple CASE (🧪 Prova-ho!)

-- CASE amb expressions booleanes
DO $$
DECLARE
    nota int := 7;
BEGIN
    CASE
        WHEN nota >= 9 THEN
            RAISE NOTICE 'Excel·lent';
        WHEN nota >= 5 THEN
            RAISE NOTICE 'Aprovat';
        ELSE
            RAISE NOTICE 'Suspès';
    END CASE;
END;
$$ LANGUAGE plpgsql;     
-- CASE amb valors
DO $$
DECLARE
    dia int := 3;
BEGIN
    CASE dia
        WHEN 1 THEN RAISE NOTICE 'Dilluns';
        WHEN 2 THEN RAISE NOTICE 'Dimarts';
        WHEN 3 THEN RAISE NOTICE 'Dimecres';
        ELSE RAISE NOTICE 'Altre dia';
    END CASE;
END;
$$ LANGUAGE plpgsql;

🔁 Bucles

🔄 LOOP bàsic (amb eixida manual)

L'estructura LOOP permet repetir un conjunt d'instruccions de manera indefinida, fins que s'indique explícitament que ha de finalitzar (EXIT). És una estructura de control iterativa (bucle).

LOOP
    instruccions;
    EXIT WHEN condicio;
END LOOP;

Molta cura o es podria fer un bucle INFINIT, colapsant el programa !!

  • LOOP indica l'inici del bucle.
  • EXIT permet eixir del bucle.
  • EXIT WHEN permet eixir del bucle quan es compleix una condició.
  • END LOOP indica el final del bucle.

Si no s'inclou cap instrucció EXIT o un altre mecanisme per finalitzar el bucle, aquest es repetirà indefinidament. !!

Exemple LOOP (🧪 Prova-ho!)

DO $$
DECLARE
    i int := 1;
BEGIN
    LOOP
        RAISE NOTICE 'i = %', i;
        i := i + 1;

        EXIT WHEN i > 5;
    END LOOP;
END;
$$ LANGUAGE plpgsql;

LOOP amb WHILE

L'estructura WHILE permet repetir un conjunt d'instruccions mentre es complisca una determinada condició.

Abans de cada iteració, es comprova la condició. Si és certa, s'executen les instruccions; si és falsa, el bucle finalitza. 

WHILE condicio LOOP
    instruccions;
END LOOP;

Exemple WHILE (🧪 Prova-ho!)

DO $$
DECLARE
    i int := 1;
BEGIN
    WHILE i <= 5 LOOP
        RAISE NOTICE 'i = %', i;
        i := i + 1;
    END LOOP;
END;
$$ LANGUAGE plpgsql;

LOOP amb FOR

L'estructura FOR permet repetir un conjunt d'instruccions un nombre determinat de vegades, utilitzant una variable de control que va recorrent un rang de valors.

A diferència de WHILE, no cal inicialitzar ni incrementar manualment la variable de control.

FOR variable IN inici..final LOOP
    instruccions;
END LOOP;

Exemple FOR

DO $$
DECLARE
    i int;
BEGIN
    FOR i IN 1..5 LOOP
        RAISE NOTICE 'i = %', i;
    END LOOP;
END;
$$ LANGUAGE plpgsql;   

DO $$
DECLARE
    i int;
BEGIN
    FOR i IN REVERSE 5..1 LOOP
        RAISE NOTICE 'i = %', i;
    END LOOP;
END;
$$ LANGUAGE plpgsql;

LABEL

En PL/pgSQL, podem utilitzar etiquetes (LABEL) per identificar un bucle o un bloc de codi. Són especialment útils quan tenim bucles niuats (un bucle dins d'un altre).

Les etiquetes permeten indicar a quin bucle volem eixir amb EXIT o en quin volem continuar amb CONTINUE.

--- Exemple
<<etiqueta>>
LOOP
    -- Instruccions
END LOOP etiqueta;  

DO $$
DECLARE
    v_i INTEGER;
    v_j INTEGER;
BEGIN
    <<bucle_extern>>
    FOR v_i IN 1..3 LOOP

        FOR v_j IN 1..3 LOOP

            RAISE NOTICE 'i=%, j=%', v_i, v_j;

            IF v_i = 2 AND v_j = 2 THEN
                EXIT bucle_extern;
            END IF;

        END LOOP;

    END LOOP bucle_extern;
END $$;

Notes addicionals

  • EXIT WHEN → surt d’un bucle en una condició
  • EXIT → surt d’un bucle "directament"
  • EXIT label → surt d’un bucle identificat amb una etiqueta. Útil si hi ha bucles niats
  • EXIT label WHEN → surt d’un bucle identificat amb una etiqueta. Útil si hi ha bucles niats
  • <<label>> → Identifica un bucle , per deprés usar EXIT label
  • CONTINUE → salta a la següent iteració
  • Els bucles poden ser niats i combinen amb IF o CASE

Bon ús d’estructures

  • Usa `FOR` si saps quantes vegades vols repetir
  • Usa `WHILE` si depens d’una condició externa
  • Usa `IF` per bifurcar el comportament del codi
  • ⚠️ Evita bucles infinits, assegura sempre una condició d'eixida

⚙️ Procediments, Funcions i Triggers

Definicions ràpides

  • Procediment: bloc PL/pgSQL que realitza una acció, pot tenir paràmetres però no retorna valor directament.
  • Funció: com un procediment, però retorna un valor mitjançant RETURN.
  • Trigger: bloc de codi que s'executa automàticament quan es produeix un esdeveniment sobre una taula (INSERT, UPDATE, DELETE).

Permisos necessaris

❗ Un usuari necessita tindre permís per executar rutines, o per crear-les i executar-es !!

-- Si sols necessita executar
GRANT EXECUTE ON PROCEDURE nom_proc TO <usuari>/<rol> [WITH GRANT OPTION];
o
GRANT EXECUTE ON FUNCTION nom_proc TO <usuari>/<rol> [WITH GRANT OPTION]; 
-- Per poder crear  ( i executar les seues)
GRANT CREATE ON SCHEMA public to usuari [WITH GRANT OPTION];  
i si no te  GRANT USAGE ON SCHEMA public to usuari [WITH GRANT OPTION];

Per defecte, PostgreSQL concedeix EXECUTE a PUBLIC en les funcions i procediments nous. Si volem restringir-ne l'execució, cal revocar aquest permís.

Vista del DD

Per vore si un usuari té estos permisos

SELECT nspname
FROM pg_namespace
WHERE has_schema_privilege(current_user, oid, 'CREATE')   -- Sustituir current_user per 'nomusuari'
  AND nspname NOT LIKE 'pg_%'
  AND nspname <> 'information_schema';

PROCEDURE – Procediment

Els procediments NO retornen valor i NO poden ser cridades dins SELECT o expressions. Poden ser cridats des de dins d'un bloc DO, directament des de linea d'ordres psql o pgAdmin, , des de dins d'un altre procediment. Des de dins d'una funció amb CALL , o des del pg_cron o altres sistemes de planificació de tasques

Exemples

--Des d'un bloc DO
DO $$
BEGIN
    CALL nom_proc();
END $$; 
--Directament des de psql o pgAdmin:
CALL nom_proc();

FUNCTION – Funció

Diferència clau:

Les funcions retornen un valor i poden ser cridades des de dins de SELECT o expressions.

Exemples

DO $$
DECLARE
  data_actual TIMESTAMP;
  valor_aleatori NUMERIC;
  data_convertida DATE;
BEGIN
  data_actual := NOW();
  valor_aleatori := RANDOM() * 99 + 1; -- equivalent a VALUE(1,100)
  data_convertida := TO_DATE('2025-04-20', 'YYYY-MM-DD');
  RAISE NOTICE '%', (SELECT UPPER(nom) FROM empleats LIMIT 1);
  RAISE NOTICE '%', (SELECT NOW());
  RAISE NOTICE '%', (SELECT sou FROM empleats LIMIT 1);
  RAISE NOTICE '%', NOW();
  RAISE NOTICE '%', data_convertida;
END;
$$ LANGUAGE plpgsql;

Diferència clau:

⚙️ Procediments en PL/pgSQL

Què és un procediment?

Un procediment és un bloc de codi PL/pgSQL emmagatzemat amb un nom que es pot cridar per executar una acció. Pot rebre paràmetres i fer servir sentències SQL, estructures de control, bucles, excepcions, etc.

Estructura bàsica

-- Definir procediment. Es fa una volta
CREATE OR REPLACE PROCEDURE saludar()
LANGUAGE plpgsql
AS $$
BEGIN
    RAISE NOTICE 'Hola!';
END;
$$;  
-- Cridar al procediment. Es pot fer moltes voltes.
-- Sempre que es necessite
call saludar();  
Nota important (seguretat) - 👉 Un procediment pot executar-se amb:
- SECURITY INVOKER (per defecte) → permisos de qui l’executa
- SECURITY DEFINER → permisos del propietari
     Si es posa , serà després de  LANGUAGE plpgsql

Procediment amb parametres

-- Definir procediment
CREATE PROCEDURE suma(a int, b int)
LANGUAGE plpgsql
SECURITY INVOKER
AS $$
BEGIN
    RAISE NOTICE 'Suma: %', a + b;
END;
$$;

--  Cridar a procediment
CALL suma(3, 4);

Tipus de paràmetres:

  • IN: entrada (per defecte)
  • OUT: eixida
  • INOUT: entrada i eixida
-- Exemple 
CREATE PROCEDURE obtenir_doble(IN x int, OUT resultat int)

Sols s'explicarem els IN, que a més a més, no cal posar la paraula IN perquè és el tipus per defecte

DEFAULT - Valors per defecte

La paraula clau DEFAULT permet assignar un valor per defecte a un paràmetre d'un procediment o funció.

Si quan es cride el procediment no s'indica cap valor per a eixe paràmetre, PostgreSQL utilitzarà automàticament el valor definit amb DEFAULT.

CREATE PROCEDURE saludar(nom text DEFAULT 'Usuari')
-- Quan es cride
CALL saludar('Juan');   -- Utilitza el valor 'Juan' que s'indica en la crida
CALL saludar();         -- Utilitza el valor per defecte
-- Les dos formes de cridar al procediment funcionaran

Els paràmetres amb valor per defecte han d'anar després dels paràmetres obligatoris (sense DEFAULT). Així, podem ometre els últims paràmetres en cridar el procediment.

Funcions en PL/pgSQL

📘 Què és una funció?

Una funció és un bloc de codi PL/pgSQL que rep zero o més paràmetres i retorna un valor. A diferència dels procediments, les funcions es poden cridar dins sentències SQL i expressions. Tambè dins de procediments o funcions. No es poden cridar amb CALL 

Exemple:
SELECT nom, UPPER(nom) FROM alumnes;
SELECT * FROM alumnes WHERE LENGTH(nom) > 5; 
SELECT now(); 
SELECT CURRENT_DATE;     
CALL now();

Funcions predefinides en postgres

Al igual que en els procediments existeixen funcions predefinides que podem utilitzar en postgresql

Tipus de Funcions Funcions
Funcions Numèriques ROUND, TRUNC, MOD, SQRT, POWER, SIGN, ABS, CEIL, FLOOR, RANDOM
Funcions de Cadenes (Strings) LOWER, UPPER, TRIM, SUBSTRING, LENGTH, REPLACE, POSITION, TRANSLATE, CHR, ASCII, INITCAP,

Funcions definides per l'usuari

I, al igual que en els procediments , podem definir noves funcions (funcions definides per l'usuari)

Hem de tindre en compte, que una funció necessita saber quin tipus de dada va a retornar, i, a més a més, en algun punt del cos de la funció, ha de retornar una dada d'aquest tipus

Estructura bàsica

CREATE [OR REPLACE] FUNCTION nom_func (  paràmetres  ) 
RETURNS tipus AS $$ 
BEGIN
    -- codi
    RETURN valor;
END;
$$ LANGUAGE plpgsql;

[OR REPLACE] en una sintaxi indica que és una part opcional, no que s'haja d'escriure literalment entre claudàtors.

Exemple simple

CREATE OR REPLACE FUNCTION suma(a integer, b integer)
RETURNS integer AS $$
BEGIN
    RETURN a + b;
END;
$$ LANGUAGE plpgsql;

OR REPLACE no permet canviar el tipus de retorn d'una funció existent. En eixe cas, cal eliminar-la (DROP FUNCTION) i tornar-la a crear.

CREATE FUNCTION doble(x INT)
RETURNS INT AS $$
BEGIN
  RETURN x * 2;
END;
$$ LANGUAGE plpgsql;

En PostgreSQL, "LANGUAGE plpgsql" es pot posar tant abans com després del bloc AS $$ ... $$, tant en funcions com en procediments. Les dos formes són correctes.

Exemple Crida des de sentència SQL 

SELECT doble(4);

Tipus de paràmetres

  • IN: entrada (per defecte)
  • OUT i IN OUT no es poden fer servir a funcions que es cridin dins SQL

Diferència amb els procediments: els procediments es criden amb CALL i poden gestionar transaccions (COMMIT i ROLLBACK) en determinades condicions. Les funcions no poden gestionar transaccions explícitament.

🚨 Disparadors (Triggers) en PostgreSQL

📘 Què és un trigger?

Un trigger és un bloc de codi PL/pgSQL que s’executa automàticament quan es produeix un esdeveniment (com un INSERT, UPDATE o DELETE) sobre una taula o vista.

Un trigger en PostgreSQL no es pot cridar manualment com una funció o procediment. Sempre s’executa automàticament quan passa un esdeveniment.

El bloc de codi del trigger s'executara:

  • BEFORE: abans de l’esdeveniment
  • AFTER: després de l’esdeveniment

Segons el cas, dins del bloc de codi, es poden utilitzar valors d’una fila abans de la operació o després de l’operació:
Per fer això s'usarà NEW. o OLD.

Nivells d’actuació

  • Fila a fila : FOR EACH ROW → actua per cada fila afectada (s'indica posant FOR EACH ROW)
  • Per esdeveniment : FOR EACH STATEMENT → actua una sola vegada per operació (s'indica no posant res)

En PostgreSQL, si no s'indica FOR EACH ROW ni FOR EACH STATEMENT, el comportament per defecte és FOR EACH STATEMENT.

Sintaxi bàsica (fila a fila)

-- 1. Crear la funció del trigger
CREATE OR REPLACE FUNCTION log_alumne_insert()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO log_alumnes(alumne_id, nom, data_insert)
    VALUES (NEW.id, NEW.nom, now());
    RETURN NEW;  -- IMPORTANT: RETURN NEW per triggers BEFORE INSERT/UPDATE
END;
$$;

-- 2. Crear el trigger.  Auditoria --
CREATE OR REPLACE TRIGGER trg_alumne_insert
AFTER INSERT ON alumnes
FOR EACH ROW
EXECUTE FUNCTION log_alumne_insert();

En triggers BEFORE: Si NO retornes correctament: RETURN NULL; 👉 es cancel·la l’operació (no s’insereix / no s’actualitza / no s’elimina)

S'ha de retornar:
BEFORE DELETE --> RETURN OLD;
BEFORE INSERT --> RETURN NEW;
BEFORE UPDATE --> RETURN NEW;
En la resta, no importa, es pot retornar NULL

Exemple: trigger per a impedir valors curts 

CREATE OR REPLACE FUNCTION check_nom_length()
RETURNS TRIGGER AS $$
BEGIN
    IF char_length(NEW.nom) < 3 THEN
        RAISE EXCEPTION 'El nom ha de tenir almenys 3 caràcters';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE OR REPLACE TRIGGER trg_check_nom    -- Impedix actualitzar si no es complix condició
BEFORE UPDATE ON alumnes
FOR EACH ROW
EXECUTE FUNCTION check_nom_length();

NEW. i OLD. representen els valors nous i antics respectivament per a cada fila.

SELECT trigger_name,
       event_manipulation AS event,
       event_object_table AS table_name,
       action_timing AS timing,
       action_statement AS function_call
FROM information_schema.triggers

Bones pràctiques

  • Usa noms clars i descripció funcional
  • Documenta el comportament del trigger
  • Evita codi complex o accions que modifiquin altres taules si no és necessari
  • Controla el rendiment: massa triggers poden degradar l’eficiència
  • Si cal registrar accions, fes servir una taula d’auditoria

🛠️ Activació i desactivació de triggers

-- Desactivar un trigger concret
ALTER TABLE nom_taula DISABLE TRIGGER nom_trigger;

-- Activar un trigger concret
ALTER TABLE nom_taula ENABLE TRIGGER nom_trigger;  
-- Desactivar tots els triggers de la taula
ALTER TABLE alumnes DISABLE TRIGGER ALL;

-- Tornar a activar tots els triggers
ALTER TABLE alumnes ENABLE TRIGGER ALL;

🗑️ Eliminar un trigger

DROP TRIGGER log_insercio ON nom_taula;

La funció associada (log_alumne_insert()) no s’esborra automàticament, només el trigger.

-- Si vols eliminar també la funció del trigger (per neteja)
DROP FUNCTION log_alumne_insert();

Seqüències en Postgresql

📘 Què és una seqüència?

Una seqüència és un objecte de base de dades que genera una sèrie de valors numèrics consecutius, normalment usats per a claus primàries, codis únics o control d’identificadors. És l’equivalent a un autoincrement en altres SGBD.

Crear una seqüència

-- Donar permís a un usuari per crear seqüències (crear objectes)
GRANT CREATE ON SCHEMA public TO usuari;

-- Crear seqüència
CREATE SEQUENCE seq_alumnes
    START 1        -- valor inicial
    INCREMENT 1    -- increment
    MINVALUE 1     -- mínim valor possible
    MAXVALUE 10000 -- màxim valor (opcional)
    CACHE 1;       -- opcional, per rendiment

-- Esborrar seqüència
DROP SEQUENCE seq_alumnes;

Ús de la seqüència

Amb funció. Per obtenir el següent valor (es pot fer servir a INSERTs)

SELECT NEXTVAL('seq_alumnes'); -- Obté el següent valor

Per consultar el valor actual (després d'haver fet NEXTVAL com a mínim una vegada):

SELECT CURRVAL('seq_alumnes'); -- Obté l'últim valor obtingut

Exemple d’ús en una inserció

INSERT INTO alumnes (id, nom, edat)  VALUES (NEXTVAL('seq_alumnes'), 'Laia', 21);

📘 Consultar seqüències existents (DD)

SELECT sequence_name
FROM information_schema.sequences
WHERE sequence_schema = 'public';  -- posar l’esquema desitjat    
 SELECT * FROM pg_sequences WHERE schemaname='public';

🗑️ Eliminar una seqüència

DROP SEQUENCE seq_alumnes;

Exemple complet

CREATE SEQUENCE seq_factura START WITH 1000 INCREMENT BY 10 ;
-- Inserció amb NEXTVAL
INSERT INTO factures (id, data_emissio) VALUES (NEXTVAL('seq_factura'), now() );

Identity Column

Una identity column és un altre mecanisme d’postgres per generar valors sencers seqüencials únics i assignar-li'ls a camps numèrics; s'utilitzen generalment per a les claus primàries de les taules garantint que els seus valors no es repetisquen.

CREATE TABLE alumnes (
    id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nom TEXT,
  .......);
  • GENERATED ALWAYS AS IDENTITY → PostgreSQL genera automàticament el valor i no permet inserir manualment un valor a la columna.
  • GENERATED BY DEFAULT AS IDENTITY → permet sobreescriure manualment el valor si cal.
    • Característica SEQUENCE IDENTITY Column
    Definició Objecte independent que genera valors numèrics seqüencials. Columna d'una taula que genera automàticament valors únics.
    Ús principal Generar claus primàries o valors seqüencials a voluntat. Generar automàticament un valor únic per fila nova.
    Com s'utilitza Cal cridar `nom_seq.NEXTVAL` explícitament en la inserció. Postgres gestiona el valor automàticament (amb `GENERATED ALWAYS` o `BY DEFAULT`).
    Control de valor L'usuari decideix quan i com consumir el següent valor. El valor s'incrementa automàticament amb cada inserció (segons la configuració).
    Flexibilitat Molt flexible: pot ser utilitzada per diferents taules o processos. Està lligada a una sola taula i columna.
    Exemple de creació CREATE SEQUENCE seq_client_id START WITH 1 INCREMENT BY 1; id NUMBER GENERATED BY DEFAULT AS IDENTITY
    Compartició entre taules Es pot usar en múltiples taules. Només es pot usar en una taula específica.

    Consultar informació de les Identity Columns (DD)

    SELECT table_name, column_name, identity_generation, start_value, increment_by
FROM information_schema.columns
WHERE identity_generation IS NOT NULL;

    Cursors en PL/pgSQL

    📘 Què és un cursor?

    Un cursor és un mecanisme de PL/pgSQL que permet recórrer múltiples files retornades per una consulta SELECT. Un cursor és com un punter que apunta a un conjunt de resultats d'una SQL i deixa llegir-los u a u.

    Serveix per treballar fila a fila amb el conjunt de resultats, com un bucle sobre una taula.

    Tipus de cursors

    • Implícits: creats automàticament per Postgres per a sentències DML (SELECT .. INTO, INSERT, UPDATE...) )
    • Explícits: definits manualment per l’usuari per tractar SELECTs que tornen múltiples files
    • FOR cursors: simplificació de l’ús explícit

    Cursors implícits

    Cursor impícit amb INTO

    No es declaren, i sols deurien tornar un resultat o fila. PostgreSQL el crea automàticament quan fas una query amb SELECT INTO.

    SELECT DESCRIPCION INTO vdescripcion from PAISES WHERE CO_PAIS = 'ESP';

    Comportament: Si no troba files, assigna NULL. Si troba diverses files, agafa la primera. Es poden consultar estes situacions amb FOUND i amb ROW_COUNT

    INTO STRICT : quan esperes que una consulta retorne exactament un registre i vulgues controlar explícitament els possibles errors.

    SELECT DESCRIPCION INTO STRICT vdescripcion from PAISES WHERE CO_PAIS = 'ESP';

    Els cursors implícits STRICT exigeixen retornar una única fila. En cas que es retorne més d'una fila (o cap fila) es produirà una excepció: Esta EXCEPCIÓ podrà ser capturada i tractada. Si no en troba cap, genera NO_DATA_FOUND; si en troba més d'una, genera TOO_MANY_ROWS. (I SQLERRM permet obtindre el missatge de l'últim error produït)

    Per salvar estes situacionses pot fer:

    SELECT count(*) INTO vcant from factura WHERE idcli = 'V00923';

    I preguntar si vcant es 1

    IF vcant=1 THEN 
    SELECT DESCRIPCION INTO vdescripcion from PAISES WHERE CO_PAIS = 'ESP';

    Cursor implícit amb FOR

    FOR r IN SELECT * FROM alumnes LOOP
   -- ús de r
END LOOP;

    Recordem: Un cursor implícit és gestionat automàticament per PL/pgSQL. No cal Obrir-lo ni tancar-lo

    -- Cursor FOR simplificat
DO $$
DECLARE
    v_alumne RECORD;
BEGIN
    -- Itera sobre totes les files de la taula
    FOR v_alumne IN
        SELECT id, nom FROM alumnes ORDER BY id
    LOOP
        -- Fer alguna cosa amb cada fila
        RAISE NOTICE 'Alumne: %, Nom: %', v_alumne.id, v_alumne.nom;
    END LOOP;
END;
$$ LANGUAGE plpgsql;

    Cursors explícits

    Es declaren. Solen tornar moltes files per després processar-les una a una. Amb FETCH

    Passos:

    1. Declarar el cursor (DECLARE)
    2. Obrir-lo (OPEN)
    3. Llegir fila a fila (FETCH)
    4. Tancar-lo (CLOSE)
    Exemple:
DECLARE c1 CURSOR FOR SELECT * FROM alumnes;
OPEN c1;
LOOP
   FETCH c1 INTO r;
   EXIT WHEN NOT FOUND;
   RAISE NOTICE '%', r.nom;
END LOOP;
CLOSE c1;

    Exemple cursor complet

    DO $$
DECLARE
    -- Cursor explícit
    c_alumnes CURSOR FOR
        SELECT id, nom FROM alumnes ORDER BY id;

    -- Variable per guardar cada fila
    v_id alumnes.id%TYPE;
    v_nom alumnes.nom%TYPE;
BEGIN
    -- Obrir cursor
    OPEN c_alumnes;

    LOOP
        -- Agafar la següent fila
        FETCH c_alumnes INTO v_id, v_nom;

        -- Comprovar si s'ha trobat alguna fila
        EXIT WHEN NOT FOUND;

        -- Fer alguna cosa amb les dades
        RAISE NOTICE 'Alumne: %, Nom: %', v_id, v_nom;
    END LOOP;

    -- Tancar cursor
    CLOSE c_alumnes;
END;
$$ LANGUAGE plpgsql;

    Bones pràctiques

    • Sempre tanca els cursors després d’usar-los
    • Utilitza FOR cursors si només necessites llegir
    • Evita FETCHs sense EXIT WHEN NOTFOUND

    Gestió d’Excepcions en PL/pgSQL

    📘 Què és una excepció?

    Una excepció és una situació d’error que es produeix durant l’execució d’un bloc PL/pgSQL. Postgresql permet capturar aquestes situacions per gestionar-les de manera controlada i evitar que el bloc falle de manera abrupta.

    Estructura general amb excepcions

    DO $$
BEGIN
    -- Codi normal
    RAISE NOTICE 'Executant codi normal';
    
    -- Exemple: forçar error
    -- RAISE EXCEPTION 'Error simul·lat';
    
EXCEPTION
    WHEN division_by_zero THEN
        RAISE NOTICE 'S’ha detectat una divisió per zero';
    WHEN others THEN
        RAISE NOTICE 'S’ha produït una altra excepció';
END;
$$ LANGUAGE plpgsql;
    --  Exemple de captura d'excepcions del cursor INTO
DO $$
DECLARE
    vdescripcion TEXT;
BEGIN
    SELECT descripcion
    INTO STRICT vdescripcion
    FROM paises
    WHERE co_pais = 'ESP';

    RAISE NOTICE 'País: %', vdescripcion;

EXCEPTION
    WHEN NO_DATA_FOUND THEN
        RAISE NOTICE 'No s''ha trobat cap país';

    WHEN TOO_MANY_ROWS THEN
        RAISE NOTICE 'La consulta ha retornat més d''un país';

    WHEN OTHERS THEN
        RAISE NOTICE 'S''ha produït un error: %', SQLERRM;
END $$;

    Tipus d’excepcions

    Excepcions predefinides

    Postgresql les reconeix automàticament.

    PostgreSQL té moltíssims tipus d’excepcions: division_by_zero, unique_violation, foreign_key_violation, etc.

    Es pot consultar la llista sencera en la documentació oficial ací

    Si vols capturar tots els errors, sempre pots posar WHEN others THEN ....

    RAISE EXCEPTION 'Missatge' interromp el flux i llança error cap a fora; RAISE NOTICE només mostra missatge sense parar el bloc.

    Excepcions no predefinides

    Postgresql les pot capturar amb SQLSTATE i SQLERRM:

    DO $$
BEGIN
    -- Operació que pot fallar
    RAISE NOTICE 'Intentant dividir per zero...';
    PERFORM 10 / 0;  -- provoca error
EXCEPTION
    WHEN OTHERS THEN
        RAISE NOTICE 'Error %: %', SQLSTATE, SQLERRM;
END;
$$ LANGUAGE plpgsql;

    🔧 Excepcions personalitzades

    Es poden declarar amb EXCEPTION i cridar amb RAISE EXCEPTION:

    DO $$
DECLARE
    my_error EXCEPTION;  -- declara excepció personalitzada
BEGIN
    -- Llançar excepció personalitzada
    RAISE EXCEPTION 'Això és un error personalitzat' USING ERRCODE = 'P0001';
EXCEPTION
    WHEN my_error THEN
        RAISE NOTICE 'S’ha capturat la meva excepció personalitzada';
    WHEN others THEN
        RAISE NOTICE 'Error desconegut %: %', SQLSTATE, SQLERRM;
END;
$$ LANGUAGE plpgsql;

    Claus d’ús

    • RAISE EXCEPTION → provoca una excepció
    • WHEN ... THEN → captura una excepció
    • WHEN OTHERS THEN → captura qualsevol error no gestionat abans
    • SQLERRM → mostra el missatge d’error
    • SQLSTATE → mostra el codi numèric de l’error

    Bones pràctiques

    • Captura errors específics abans de fer servir OTHERS
    • Informa l’usuari o registra l’error
    • No captures OTHERS sense mostrar cap missatge (silenciar errors és perillós)
    • Fes servir excepcions personalitzades quan tingues validacions pròpies

    📅 Tasques automatitzables en PostgreSQL

    Què es pot automatitzar?

    En un entorn Postgresql, és habitual automatitzar tasques per millorar la gestió i el rendiment del sistema. Algunes de les tasques més comunes són:

    • Exportacions i còpies de seguretat
    • Importacions de dades
    • Execució d'informes
    • Neteja de logs i arxius antics
    • Tasques de manteniment periòdic

    📄 Scripts SQL .bat i .sh :

    Els scripts SQL i els scripts .bat o .sh són fitxers que contenen instruccions que podem executar automàticament per realitzar determinades tasques. La diferència principal és el tipus d'instruccions que contenen i qui les interpreta.

    • .sql (ordres sql): Contenen instruccions SQL (consultes, insercions, actualitzacions, crides a funcions i procediments, etc.). Es poden executar mitjançant psql amb l'opció -f .(Estes ordres SQL tambè es poden executar des d'un procediment)
    • .sql (amb metacomandes) : Poden contindre instruccions SQL i metacomandes de psql. Es poden executar mitjançant psql amb l'opció -f . Les metacomandes no es poden executar des d'un procediment
    • .bat . Són scripts de Windows que contenen ordres del sistema operatiu. Permeten executar programes com psql, cridant a scripts .sql .psql i comandes directes amb "-c "CALL el_meu_procediment();"".
    • .sh : Són scripts habitualment utilitzats en Linux que contenen ordres del sistema operatiu. Igual que els .bat

    Exemple: script SQL + psql

    -- arxiu: informe.sql
\pset pager off       -- desactiva el paginador
\o informe_resultats.txt  -- envia l'eixida a fitxer
SELECT * FROM alumnes;
\o                    -- torna l'eixida a la consola
\q                    -- ix de psql

    🖥️ Script .bat (Windows)

    -- Un .bat llança el informe.sql
@echo off
psql -U postgres -d institut -f informe.sql
pause

    🐧 Script .sh (Linux)

    -- Un .sh llança el informe.sql
#!/bin/bash
psql -U postgres -d institut -f informe.sql  

    chmod +x executar.sh
./executar.sh

    Les ordres que comencen per \ (\pset, \o, \q, etc.) són metacomandes pròpies de psql, no instruccions SQL estàndard. Per això, el fitxer s'ha d'executar amb psql i no directament des d'un altre client SQL.

    Exemple: procediment de postgres

    pg_cron i pgAagent

    Tant pg_cron com pgAgent permeten programar tasques automàtiques (jobs) en PostgreSQL. La diferència principal és que pg_cron està integrat dins del servidor PostgreSQL com una extensió, mentre que pgAgent funciona com un servei o procés independent que consulta la base de dades per saber quines tasques ha d'executar.

    📆 pg_cron

    Postgresql disposa d'una extensió del sistema per programar tasques (anomenades jobs ) directament des de DINS la base de dades: pg_cron.

      pg_cron
    • S'instal·la com una extensió de PostgreSQL.
    • Les tasques es defineixen DINS de la bbdd mitjançant instruccions SQL.
    • Utilitza una sintaxi de programació semblant a la de Linux cron.
    • Permet executar consultes SQL, funcions i procediments.
    • Les tasques es gestionen des de la base de dades.

    Primer s'ha d'instal·lar en el SO

       Linux
sudo apt install postgresql-XX-cron

    Cal substituir XX per la versió de PostgreSQL instal·lada

    -- En postgresql.conf
shared_preload_libraries = 'pg_cron'
-- Per fer que cron server s’inicialitze automàticament   
    cron.database_name = 'postgres'
-- També es pot indicar en quina base de dades es crearà la configuració de pg_cron:
-- Per defecte, s'utilitza la base de dades postgres

    Important: pg_cron només es pot instal·lar en una base de dades per clúster PostgreSQL.
    ** Es poden programar tasques en altres bases de dades mitjançant cron.schedule_in_database().

    ⚠️ IMPORTANT: Després de modificar shared_preload_libraries, cal reiniciar el servidor, sudo systemctl restart postgresql

    En Windows és un poc més complicat,perquè s'ha de compilar codi font.

    Usar extensió

    CREATE EXTENSION IF NOT EXISTS pg_cron;

    pg_cron només permet que un superusuari cree jobs.

    Els jobs s’executen amb els privilegis del rol que els crea.

    Si cal més granularitat s'usarà una altra eina, com pgAgent de pgAdmin

    Crear una tasca programada

    SELECT cron.schedule(
    'job1',
    '* * * * *',
    $$CALL el_meu_procediment();$$
);

    El rol que executa el job ha de tenir permisos per executar el SQL o procediment definit dins del job.

  • GRANT EXECUTE ON PROCEDURE nom_procediment TO usuari;
  • GRANT SELECT, INSERT, UPDATE, DELETE ON taula TO usuari;

    • L’usuari 'usuari' no necessita ser superusuari per executar el job, només per cridar els procediments que té permís.

    * Les expressions cron segueixen el format Linux: min hora dia_mes mes dia_setmana

    * Els jobs s’executen dins de la BD, amb permisos del rol que crea el job.

     ┌───────────── min (0 - 59)
 │ ┌────────────── hour (0 - 23)
 │ │ ┌─────────────── day of month (1 - 31) or last day of the month ($)
 │ │ │ ┌──────────────── month (1 - 12)
 │ │ │ │ ┌───────────────── day of week (0 - 6) (0 to 6 are Sunday to
 │ │ │ │ │                  Saturday, or use names; 7 is also Sunday)
 │ │ │ │ │
 │ │ │ │ │
 * * * * *     
    -- Exemples
'10 seconds'  # every 10 seconds
* * * * *     # every minute
*/5 * * * *   # every 5 minutes
0 * * * *     # every hour
0 0 * * *     # daily at 12AM
0 0 * * 1-5   # 12AM every weekday
0 1 * * 0     # 1AM every Sunday
0 13 2 6 *    # 1PM on the 2nd of June

    Habilitar o deshabilitar la programació

    -- Deshabilitar
UPDATE cron.job
SET active = false
WHERE jobid = 1;

-- Habilitar
UPDATE cron.job
SET active = true
WHERE jobid = 1;

    Els jobs desactivats no s’executen però romanen a la taula cron.job.

    Modificar un job

    -- change job's schedule
SELECT cron.alter_job(42, '0 10 * * *');
-- returns void

    Esborrar un job

    SELECT cron.unschedule(jobid);

    🕰️ pgAgent , integrat en pgAdmin

    • S'instal·la com un programa o servei independent del servidor PostgreSQL.
    • Consulta periòdicament la base de dades per comprovar si hi ha tasques pendents.
    • Permet automatitzar execucions de SQL, funcions, o scripts del sistema operatiu segons horaris definits.
    • Permet definir tasques compostes per diversos passos (steps).
    • Permet definir horaris i diverses planificacions per a una mateixa tasca.
    • S’integra amb pgAdmin, així pots crear, modificar i supervisar tasques gràficament.
    • Funciona com un servidor/servei que s’executa constantment i comprova les tasques programades.
    -- Exemple de job amb steps:  Job: Manteniment nocturn
Pas 1: SQL  Executar un procediment d'actualització de dades.   CALL actualitzar_dades();
Pas 2: SQL  Eliminar registres antics.   DELETE FROM registres WHERE data < CURRENT_DATE - 365;
Pas 3: Sistema operatiu    Executar un script de còpia de seguretat.   ./copia_seguretat.sh

    pgAgent no necessita que pgAdmin estiga obert ni en funcionament les 24 hores. El que necessita estar en funcionament és el servei pgAgent.

      Els tres components:
    • PostgreSQL: el servidor de bases de dades on es guarden les definicions dels jobs i la seua planificació.
    • pgAgent: el servei independent que comprova les tasques programades i les executa quan arriba el moment.
    • pgAdmin: l'eina gràfica que permet configurar i administrar els jobs, però no és responsable d'executar-los.

    El servidor PostgreSQL i el servei pgAgent no necessiten estar instal·lats en el mateix ordinador. pgAgent pot funcionar en un ordinador diferent del servidor PostgreSQL, sempre que puga connectar-se a aquest mitjançant la xarxa.

      Per tant:
    • El servidor PostgreSQL ha d'estar accessible des de l'ordinador on funciona pgAgent.
    • pgAgent necessita credencials i permisos per connectar-se a PostgreSQL.
    • La connexió de xarxa ha d'estar disponible quan s'hagen d'executar les tasques.
    • Si pgAgent executa scripts del sistema operatiu (.bat, .sh), aquests s'executaran en l'ordinador on està instal·lat pgAgent, no necessàriament en el servidor PostgreSQL.

    En general, es recomana instal·lar pgAgent en el mateix servidor que PostgreSQL, especialment en instal·lacions xicotetes o mitjanes. No obstant això, no és un requisit: també pot funcionar en una màquina independent.

    Per poder usar pgAgent, primer s'ha d'instal·lar des del sistema operatiu. Després, crear una extensió.

    Des de Linux

sudo apt install -y pgagent

    Executar pgAgent com a servei

    SQL dinàmic

    En algunes tasques de manteniment, s’utilitzarà el diccionari de dades (amb un cursor)- i per a cada objecte de DD s’aplicarà una sentència DDL

    Si esta sentència correspon al DDL, no es pot executar directament dins d'un bloc de codi

    En este cas, es farà ús de la sentència EXECUTE

    EXECUTE és una instrucció de PL/pgSQL que permet executar sentències SQL dinàmiques és a dir, sentències construïdes en temps d'execució com cadenes de text.

    Exemple

    CREATE OR REPLACE PROCEDURE defrag_taules(vschema text)
LANGUAGE plpgsql
AS $$
DECLARE
    x RECORD;
    sql_cmd text;
BEGIN
    -- Recorre totes les taules de l'esquema
    FOR x IN
        SELECT tablename
        FROM pg_tables
        WHERE schemaname = vschema
    LOOP
        -- Construir sentència SQL dinàmica
        sql_cmd := 'VACUUM FULL ' || quote_ident(vschema) || '.' || quote_ident(x.tablename) || ';';
        
        -- Executar SQL dinàmic
        EXECUTE sql_cmd;
        
        -- Mostrar missatge
        RAISE NOTICE 'Taula desfragmentada: %', x.tablename;
    END LOOP;
END;
$$;

    PostgreSQL EXECUTE només funciona dins de PL/pgSQL, no pots executar DDL dinàmic directament dins de SQL normal.

    Sempre és recomanable utilitzar quote_ident() per evitar injeccions SQL o errors amb noms especials.

    CALL defrag_taules('public');
